# @speakkit/ui

The real Lumen components for SpeakKit: same geometry, states, icon placement and behaviour as the Lumen design file, as one stylesheet (`lumen.css`, the contract) plus React components and a tiny vanilla builder module that emit identical markup (for the content script, Shadow DOM, no React).

Spec: `docs/lumen-components.md` and `spec/lumen-spec.json` (read from the `.figcraft` file). Reference PNGs: `docs/lumen-components/`.

## Use

React:

```tsx
import "@speakkit/ui/lumen.css";
import { Button, Toggle, Select, SettingsSection, SettingRow } from "@speakkit/ui";

<div className="lm" data-theme="dark"> {/* "lm" is required; data-theme optional (default: prefers-color-scheme) */}
  <Button variant="primary" iconLeft="arrow-narrow-up">Send</Button>
  <Toggle aria-label="Highlight words" defaultChecked onChange={(on) => {}} />
</div>
```

Vanilla (content script, Shadow DOM):

```ts
import css from "@speakkit/ui/lumen.css?inline";
import { h, icon, button, iconButton, toggle, pill, kbd, tooltip } from "@speakkit/ui/vanilla";

const root = h("div", { class: "lm", "data-theme": "dark" });
shadow.append(h("style", null, css), root);
root.append(button({ variant: "primary", iconLeft: "player-play", label: "Read" }), toggle({ checked: true, label: "Highlight", onChange }));
```

Theme: `:root`, `:host` and `[data-theme=dark|light]` define the 22 `Lumen / Color` tokens as CSS variables (`--surface-card`, `--text-primary`, `--accent-default`, `--tag-red` ...); `prefers-color-scheme: light` applies when no `data-theme` is set. Never hard-code hex values in components, use the variables.

Icons: Tabler outline (MIT), inlined from `src/icon-data.ts` (generated by `node scripts/gen-icons.mjs`; add a name to the list in that script to ship another icon). Every icon is a `display:block` 24-unit svg sized by `--s`; the stroke stays 1.5 px on screen at every size (`stroke-width: calc(36 / var(--s))`), which is what the file does. Icons are centred by flex parents (`align-items: center`), never inline-baseline.

States are real CSS (`:hover`, `:active`, `:focus-visible`, `:disabled`, `[aria-*]`). `.is-hover`, `.is-pressed`, `.is-focus` force a state (gallery, tests). Motion: 83 ms hover, 167 ms press and menus with `cubic-bezier(0,0,0,1)`, 250 ms panels, 333 ms progress; `prefers-reduced-motion` keeps fades only and stops loops.

## Decisions where the file is ambiguous

- Focus ring: 2 px accent. The board header says 2 px offset but the drawn nodes (buttons, pills, icon buttons, toggle button) have none, so those use `--lm-ring-offset-drawn: 0`; everything not drawn (toggle, tabs, segmented, select, menu items, nav) uses `--lm-ring-offset: 2px`. Both are variables on `.lm`.
- Toggle: the screen toggle (32x18, knob 14, off = fill/selected) is the default; `board` gives the 40x20 board geometry.
- Text input focus: stroke becomes 2 px inside and, as in the file, counts toward layout (content shifts 1 px).
- Secondary and danger buttons keep their size on focus (the file's focus frame is 2 px narrower because the stroke is dropped from the hug width).
- Not in Lumen, designed from tokens and flagged: `Slider`, modal scrim (`--lm-scrim`), shimmer on `Skeleton`.

## Accessibility

`Toggle` is a `role="switch"` button (Space/Enter). `Select` is a listbox popup (Arrow keys, Home/End, Enter/Space, Escape, Tab, outside click). `Menu` uses roving focus, `Tabs` and `Segmented` roving tabindex with arrow keys, `Modal` traps focus, closes on Escape and restores focus, `Tooltip` shows on hover and keyboard focus, `IconButton` requires `label`.

## Gallery and visual check

```
pnpm exec vp build --config vite.config.ts      # builds gallery to out/gallery
pnpm exec vp dev --config vite.config.ts        # live gallery, dark and light, same arrangement as the board
node scripts/compare.ts [--only text] [--theme dark|light] [--no-build]
```

`compare.ts` screenshots each `[data-spec]` cell at 2x with Chromium (isolated on the page background, with the ring/shadow bleed the file's export includes), blends the reference PNG on the same backdrop and writes `out/compare/<id>-<theme>.png` (reference | mine | diff) plus `report.json`. Columns: `elDelta` is element size minus reference size (CSS px), `diff%` pixelmatch at threshold 0.1, `hard%` pixels differing by more than 24 per channel (text anti-aliasing: the file's Inter is the static font, the browser uses the system variable Inter), `fill` compares the dominant colour exactly.

Tests: `pnpm exec vp test run` (markup via react-dom/server, behaviour in Chromium against the built gallery).

Type-check: `pnpm exec tsrs --noEmit -p packages/ui`.
