# Ostio Files engineering practices, extracted for Speak Kit

Written 2026-11-01 from `D:/workspaces/ostio-files/docs/ostio-files-architecture-development-flow` (pages 00 to 16, CLAUDE.md, DECISIONS.md, PERF.md, REVIEW.md, adr/, agents/, intake/, references/). Ostio Files is an Electron + Rust file manager with an extension platform, written and reviewed almost entirely by agents, with every rule tied to a CI gate. This file lists its practices as rules so Speak Kit can be refactored toward them without rereading the sources. The gap analysis and work packages are in `refactor-plan.md`.

## How to read this file

Each bullet is one rule, written as the behaviour wanted, with an ID and its source in brackets. After the source comes the Speak Kit verdict:

- **A**: applies to Speak Kit as written.
- **Adapt**: applies; the Speak Kit form is stated.
- **N/A**: does not apply; the reason is stated. N/A rules are kept so nobody re-derives them.

Source keys:

- `[00]` to `[16]`: the numbered pages; `§NN` is the numbered section on that page.
- `[DEC §x]`: DECISIONS.md (`§1.n` is principle n, `X7` is addendum X7). `[PERF]`: PERF.md. `[REVIEW R8]`: REVIEW.md item.
- `[CLAUDE §n]`: Ostio CLAUDE.md. `[OPM §n]`: agents/AGENT-OPERATING-MODEL.md. `[PROP §n]`: references/philosophy/PROPOSAL.md.
- `[ADR 0007]`, `[INT tsrs]`: adr/ and intake/ notes. `[REF vscode 3.8]`: a finding in references/. `[DESLOP]`: agents/skills/de-slop/SKILL.md.

Two things to keep in mind while reading:

1. Ostio is much bigger than Speak Kit. A rule is kept when its idea transfers even if Ostio's mechanism (Rust core, extension hosts, Effect, dependency-cruiser) does not.
2. Ostio's numbers (300 lines, complexity 15, 50 ms task, 10 ms loop delay) are its own calibrated limits. They are used here as the defaults to start from; a Speak Kit number that is measured and recorded in `docs/perf.md` wins over an Ostio number.

## 1. Architecture and process model

- **A1** Listing, scrolling, typing, selection and copy never wait on network, extension code, event listeners or any slow process. Late data arrives as a patch to what is already shown. [00 §01; 12 §02 N1; DEC §1.1] **Adapt:** for Speak Kit the input path is popup open, Listen, seek, pause and speed change. None of them awaits a health check or a model load; the designed loading state shows, then the data patches in.
- **A2** A loop per entry, byte or OS handle runs in native code or a worker. Only per-gesture work runs on the UI thread or the main loop. [00 §01; DEC §1.3] **Adapt:** synthesis, resampling, MP3 encoding, document parsing, OCR and Readability run in a worker or child process, never on Electron main or a renderer UI thread.
- **A3** Menus, buttons and skeletons are drawn from a cached index, without running feature code. [00 §01; 07 §04] **N/A** as an extension feature. **Adapt:** popup and dock draw the last known state from storage before the first health reply.
- **A4** Pay only for what is used: lazy activation, lazy tabs, reaped idle processes, unmounted hidden UI, no idle timers. [00 §01; 12 §02 N7] **A.**
- **A5** Messages carry ids and ranges. Bulk data is binary, copied once per process hop, in frames up to 1 MiB. Never JSON arrays of entries, never one call per row. [00 §01; 02 §06; CLAUDE §1] **A** (audio frames are binary; library blocks are paged).
- **A6** Platform differences are named features computed once and normalized in one place. UI checks features, never the OS name. An absent feature is reported (`NotSupportedOnPlatform`), never faked. `process.platform` appears only in platform folders and entry files. [00 §01; 11 §05; CLAUDE §5] **Adapt:** Speak Kit is Windows-only. Keep the few `process.platform` sites behind one `platform` module so a second OS adds one file.
- **A7** Every registration returns a Disposable. Every request carries an id, a generation and a deadline. Every native boundary is supervised with restart limits. [00 §01; 02 §06] **A.**
- **A8** Budgets are tests. A budget without a CI assertion is a wish. [00 §01; 12 §00] **A.**
- **A9** A failure of one feature (engine missing, crash, denied permission) degrades that feature and never blocks the user's own data. [00 §01; DEC §1.10] **Adapt:** library documents stay readable and exportable while the engine is down.
- **A10** The design file decides how the UI looks. Code matches the frame, and the frame id is in the commit or screenshot name. [00 §01; CLAUDE §15, §23; 13 §15] **A.**
- **A11** The process model is a table: process, count, runtime, what it owns, start/stop rule, memory budget. A new process type needs an ADR and a budget line. [02 §04; 00 §02] **A.**
- **A12** The supervising main process hands out ports and stays off the data path. Main event-loop delay p99 is at most 10 ms and a host loop at most 5 ms, measured with `perf_hooks.monitorEventLoopDelay` under a hostile load test. [02 §06 rule 11; 12 §02 N2] **Adapt:** Speak Kit runs the loopback server inside Electron main, so server, IPC and import work all count against the 10 ms budget.
- **A13** Supervision: restart a crashed child only if it crashed fewer than 3 times in 5 minutes, otherwise mark it failed and show it. 3 s without an ack means unresponsive: kill and restart. Show "Reconnecting..." during a restart. [02 §08] **Adapt:** the Kokoro model host and the Python sidecar.
- **A14** Startup phases: starting (incoming opens wait in a queue), ready (first window with skeleton), restored (first content painted), eventually (restored + 2 s idle: update check, prewarm). No network call before first paint. [02 §07; 14 §11; REF diffity 3.8] **Adapt.**
- **A15** Window defaults: sandbox true, contextIsolation true, no Node in renderers, spellcheck false, backgroundThrottling true, native occlusion on, V8 code cache on. [02 §07; 14 §02] **A.**
- **A16** V8 code cache (ADR 0008): main window `v8CacheOptions: "bypassHeatCheck"`, cache directory `<userData>/CachedData/<buildId>`, a cleaner removes other build directories 30 s after restored, `module.enableCompileCache()` for Node processes. Ostio did not benchmark it. [ADR 0008] **Adapt:** optional; measure cold start first.
- **A17** Startup time is measured with named `perf.mark` calls shared across processes. CI start-up assertions read the same marks so a regression names its phase. [REF vscode 3.8] **Adapt.**
- **A18** Profile layout: user-editable settings JSON validated by a schema, caches outside the profile, secrets only in the OS keychain, separate profiles for nightly and beta. [DEC X9; 14 §04] **Adapt** (secrets: see S9).
- **A19** Logs are structured JSON lines per process with request ids, written by a background writer, rotated 5 x 10 MB, paths hashed at `info`, kept local, attached to a crash report only with consent. A disabled level costs at most 50 ns. [DEC X7] **Adapt.**
- **A20** Recovery: a broken settings or session file is kept as `*.bad`, the app starts with defaults and tells the user. Derived caches are rebuilt, never repaired in place. [DEC X8, §17.10 rule 4] **A.**
- **A21** No usage analytics. Crash reports are opt-in. Every network call is listed on a privacy page with when it fires and what it sends. [14 §11, §12] **Adapt:** write the page (Speak Kit has no telemetry).
- **A22** The resident cost of staying ready is a visible setting. [02 §05] **A** (the idle-unload window setting exists).
- **A23** N/A group. Rust core and napi addon, core host utilityProcess, MessagePort brokering, the resident agent, win-shell-host, T3 native helpers, system surfaces (launcher, Hub, tray menu extensions, dialog picker, desktop takeover), app modes, macOS preview and the 8-week release plan. [00; 02; 06; 11; 15] **N/A:** Speak Kit has no native core, no extension host and no out-of-window surfaces. The rules they imply that do transfer are A1 to A22 and F1 to F25.

## 2. Package graph and boundaries

- **P1** Dependencies point one way. One root package (Ostio: `ostio-protocol`, generated into `@ostio/contract`) imports nothing else in the workspace. Apps and binaries sit above it. [04 §00, §01] **A:** `@speakkit/protocol` is the root.
- **P2** Packages never import `apps/*`. [03 §09; 04 §04] **A.**
- **P3** A package exists only with a second consumer or a published API. No Turborepo, Nx or Bazel. [03 §03; 04 §07; 01 §03] **A.**
- **P4** Generated files are never edited by hand. CI regenerates them and fails on a diff. [04 §02; CLAUDE §1] **Adapt:** `tokens.ts`, `icon-data.ts`, `logo-data.ts` each need a staleness test (only `tokens.ts` has one).
- **P5** The public SDK imports only contract types and disposables; built-in extensions import only what a third party can. [04 §04] **N/A:** no SDK or built-in extensions.
- **P6** Import bans by environment: Electron only under `main/` and the main/preload entries; Effect only in trusted processes; `bun:*` only in tooling; `process.platform` only in platform folders and entries. Raw `ipcRenderer`, `postMessage` and `process.send` only inside the one rpc layer. [04 §04, §05; 02 §06; CLAUDE §1] **Adapt:** Electron only in desktop `main/` and `preload/`; Node built-ins never in renderers, content scripts or `packages/player`; `chrome.*` only in extension entries and one storage/messaging port; `ipcRenderer` only in `preload/`.
- **P7** No import cycles (checked on compiled output). No barrel file that re-exports a whole feature. [04 §04; 03 §09] **A.**
- **P8** No files named `utils`, `helpers`, `common` or `misc`; a folder named `common/` inside a feature is allowed. [03 §09; CLAUDE §2; C22] **A.**
- **P9** Import rules are deny-by-default and enforced by a tool. A `docs/LAYERS.md` is generated from the rule config. [04 §04; DEC §17.6] **Adapt:** Speak Kit already uses oxlint `no-restricted-imports` overrides in `code/vite.config.ts`; extend those and generate LAYERS.md from them.
- **P10** Inside an app, code is split by environment: `common <- {main, renderer, host}`; no sideways imports between environments; one tsconfig per environment; `entries/` is the only place that composes layers. [03 §04] **Adapt:** desktop `shared <- {main, preload, renderer}`; the renderer never imports `main/` and `main/` never imports `renderer/` (only the first is enforced today); each process has one composition root.
- **P11** A feature is a folder with one anatomy: a registration file, an interface file other features import, contributions as data, pure `common/`, process folders, dumb UI, `testing.ts` fakes, colocated tests, its own l10n keys. [03 §05; 13 §02; DEC §17.2] **Adapt:** Speak Kit has no DI registry, so `index.ts` is the interface (header + named exports only), pure logic in `model.ts` or `reducer.ts`, UI in components/hooks, `testing.ts` for fakes, tests next to code.
- **P12** A module's declared `imports` equal the features whose interface it actually imports, checked by a tool. [DEC §17.2, §17.6] **Adapt:** no declaration; generate `docs/MODULES.md` (imports, imported-by, export count) from the code and fail CI when it is stale.
- **P13** Rust crate rules (OS crates only in the platform crate, headless core, cargo-deny wrappers, shared module names across Rust/TS/protocol). [04 §01, §03] **N/A.**
- **P14** Dependencies: exact pins in one catalog (`pnpm-workspace.yaml`), `packageManager` pinned, pnpm `minimumReleaseAge` of 7 days, lockfile-only installs in CI, install scripts only on an allowlist. [01 §07; 14 §03; DEC §14.10] **A.**
- **P15** Every direct dependency is admitted by a recorded decision (allowlist citing the ADR or section), checked in CI. Copying library code into the repo counts as adding the dependency. [OPM §4.1; CLAUDE §17] **Adapt:** a script checks that each direct dependency is named in `docs/decisions/0001-stack.md` (the rule already exists in Speak Kit's CLAUDE.md without a check).
- **P16** New tools and libraries go through intake: note, screen, spike outside the repo, ADR, decision, adopt behind a flag, review within 8 weeks. Hard criteria: permissive licence, a release in the last 6 months, the adopted version at least 14 days old, supports Windows, fits every budget, removal plan, no overlap with the stack, no unreviewed install scripts. [OPM §4.3; CLAUDE §17; 16 §07] **Adapt:** Speak Kit's "search npm and GitHub first, compare, record in 0001-stack" is the short form; add the 14-day and 6-month criteria.
- **P17** A platform built-in or an existing dependency beats a new dependency. "Smaller is better." [OPM §4.3; 16 §07] **A** (already in Speak Kit's CLAUDE.md).
- **P18** Type checking: the blocking checker is `tsc`; the Rust port (`tsrs`) runs as a second non-blocking job. It becomes blocking only through an ADR after 2 weeks of identical diagnostics and a measured CI gain. [INT tsrs] **Adapt:** Speak Kit made tsrs the only checker; add the second check or record the decision.
- **P19** TypeScript flags: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noImplicitOverride`. [01 §03; DEC §2] **A.**
- **P20** Tooling scripts may use Bun; nothing Bun-specific ships. [00 §06; 03 §11] **N/A:** Speak Kit uses Node scripts.

## 3. UI architecture

- **U1** The state of every feature, panel, dialog and flow is a pure reducer `(state, action) => state` in `common/`. Actions are a discriminated union and the switch is exhaustive (`const unreachable: never = action`). [13 §03; DEC §17.4] **A.**
- **U2** Components are dumb: they dispatch actions and read through fine-grained selectors that return primitives or stable references. [13 §03; DEC §7.9, §17.4] **A.**
- **U3** Reducers and components run no side effects. An action that needs I/O goes to an effect handler or an async port that dispatches a result action (`listing/pageLoaded`, `ops/failed`). [13 §03; DEC §17.4] **A.**
- **U4** Multi-step flows (rename, drag, conflict, consent, wizard, mode switch) are hand-written state tables, `state x event -> state`. No XState. No immer in hot reducers. [13 §03; 01 §04] **A:** Speak Kit's wizard, export dialog, add-document dialogs and update flow.
- **U5** State is normalized by id, reducers are O(1) or O(log n), dispatch takes at most 1 ms, and bulk data (rows, document text) never lives in a store. [13 §03; 05 §11; DEC §17.4] **A.**
- **U6** Reducers and predicates are tested in Node without a browser: table-driven, literal expected values, plus `fast-check` properties. They are the fastest tests and the first ones written. [13 §10; DEC §17.4] **Adapt:** `fast-check` is optional (new dependency, needs an entry in 0001-stack).
- **U7** Each view is wrapped in one React error boundary that shows a fallback or a "Reload" placeholder and reports the render error once as a defect. [DEC §17.10 rule 3] **A.**
- **U8** Hidden UI is unmounted and costs 0 CPU. A hidden spinner is unmounted or `animation: none`, not merely hidden. [05 §11; REF files 5.11] **A.**
- **U9** Window chrome never moves; tab chrome swaps contents; only the content layer animates. Animated properties are `opacity` and `transform` only; `will-change` is set only during the animation; input is never blocked during a transition. Fade through is 70 ms out and 110 ms in, scale 0.985 to 1; reduced motion is a crossfade of at most 150 ms. [05 §10; DEC §7.8] **Adapt:** Speak Kit's motion tokens live in Lumen; the constraints (compositor properties only, input never blocked, reduced motion honoured) apply as is.
- **U10** Every interactive state gets a short micro-animation taken from tokens (`motion.*`); components never contain literal milliseconds or curves; the design file's motion page is read before building any motion. [DEC §7.8a; CLAUDE §23] **Adapt:** tokens already exist in `lumen.css`; add a check for literals.
- **U11** React Compiler (via OXC) behind a flag; no manual `useMemo`, `useCallback` or `memo` except two documented list boundaries; any other use needs a React Profiler measurement linked in a comment; budgets are asserted on the configuration each channel ships. [13 §04; DEC §17.5] **N/A until the compiler is adopted.** Meanwhile keep manual memoization only where a measurement justifies it.
- **U12** oxlint `react-hooks` rules are errors, so the compiler (and reviewers) can rely on the Rules of React. [13 §04] **A.**
- **U13** Lists use fixed row heights and a virtualizer; no `measureElement`. [01 §03; 12 §03] **N/A:** Speak Kit's lists are short; revisit if the library grows to thousands of rows.
- **U14** One UI kit built on tokens only; apps compose it and do not re-implement it. Tokens are generated from one source and never hand-edited. [04 §02; 14 §07] **A:** `@speakkit/ui` and `lumen.css`.
- **U15** Accessibility by construction: roving tabindex, every control reachable by keyboard, OS reduce-motion, reduce-transparency and increase-contrast honoured, UI scale 90 to 150 %, announcements debounced and never per row. CI runs axe on the screens. [DEC X10] **A** (Speak Kit already has axe specs).
- **U16** Every feature brief says what loads immediately (what the first frame needs, within budget) and what loads lazily as a designed loading state. A slow source never blocks first paint and never reorders what the user already sees. [CLAUDE §23] **A.**
- **U17** Design first: every scenario and state (light, dark, empty, error, loading), edge cases (very long names, many items) and every sub-scenario is drawn before code, and the user approves the designs per area before development starts. [CLAUDE §23] **Adapt:** Speak Kit's `designs/` and `docs/scope.md` already map frames to code.
- **U18** Window, region, slot and action model (10 regions, ActionItem as data, overflow toolbox arithmetic, user-defined actions), layout presets, app tabs, app modes, per-tab state limits, selection ranges tagged with generation. [05; 06] **N/A:** no window shell model. One idea transfers: list data (tray menu items, palette entries) is data, not JSX.

## 4. Events and data flow

- **E1** Hooks are the app's own events. Observe events are the primary kind: after the fact, batched, coalesced, filtered at the producer before IPC. A topic with no subscriber costs one bit test. [09 §02, §03] **Adapt:** the desktop pushes a full `AppState` snapshot to every window on each `publish()`; coalesce to one send per frame and skip hidden windows.
- **E2** Events carry ids, not objects, plus origin and cause. Startup emits one `ready` snapshot, never a storm of `didCreate`. [09 §04] **Adapt.**
- **E3** UI events are published after the reducer commits, in a background task, at most one batch per frame, at most 0.05 ms per action. [09 §03; 13 §03] **Adapt:** applies to state broadcasts between desktop main and windows.
- **E4** Queues are bounded (Ostio: 2,000 events or 512 KB per subscriber, 16 MB total). On overflow the backlog is dropped, one overflow marker is sent and the consumer resyncs through a documented call per topic. [09 §03, §08] **Adapt:** every queue in Speak Kit has a cap and a defined overflow behaviour (stream queue `maxQueue` 8 and 429 exist; the activity list and export job list need the same statement).
- **E5** Producers never wait on consumers: emit is an O(1) append. [09 §03] **A.**
- **E6** Hot-path data (hover, scroll, per-keystroke text, completion of a thumbnail) is not an event; it stays a direct provider contract. [09 §05] **A.**
- **E7** Every cross-process call goes through one typed channel. Raw `ipcRenderer`, `postMessage` and `process.send` elsewhere are lint errors. [02 §06; CLAUDE §1] **Adapt:** preload is the only user of `ipcRenderer` today; add the lint rule.
- **E8** Wire frames: request, ack, reply, cancel, event-batch, ping. A version handshake at connect. Golden frames per protocol version. [02 §06 rule 3] **Adapt:** Speak Kit has `frames.ts` plus tests and an `apiVersion` mismatch error; add golden frames for the binary codec.
- **E9** Every request carries id, generation and `deadlineMs`. Replies from stale generations are dropped. The ack is sent on receipt, before work starts. [02 §06 rule 4] **Adapt:** `X-SpeakKit-Replace` is the generation; add deadlines to `/v1/speak`, warm, hold and export calls.
- **E10** Cancellation: `AbortSignal` at JS edges, an explicit `cancel(opId)` on the wire, a polled token in native loops (checked at least every 1,000 entries or 10 ms). [02 §06 rule 6; 13 §07] **A.**
- **E11** Interactive and background work run in separate lanes. Background work cannot starve interactive work. Background loops also check an "interactive busy" flag. [10 §06; 12 §02 N3] **Adapt:** exports and reads share the same synthesis slots today.
- **E12** Late data is a patch applied once per animation frame; the row shows a placeholder until then. Sorting or filtering starts a new generation and stale results are dropped. [10 §01, §02, §05] **N/A** for listings. **Adapt** for streamed audio and document loading: stale results of a replaced request are dropped.
- **E13** Watcher events are hints: coalesce, apply keyed patches, rescan on overflow, never refetch a whole folder per event. [10 §07; CLAUDE §12] **N/A** (the clipboard watcher polls once per second and holds no tree).
- **E14** Row batches: columnar ArrayBuffers of up to 2,048 rows built within a 12 ms slice, `EntryId` per row, first 128 rows pushed at once. [10 §01, §04] **N/A.**
- **E15** Observe/participate/transform hook kinds, the event catalogue, participant deadlines (500 ms / 1.5 s), veto, automation rules, `events --follow` CLI, extension-defined events, loop guard. [09 §02 to §08] **N/A:** no third-party code or automation layer.

## 5. Extension points

- **X1** The public API surface is small and typed (Promise + `AbortSignal` + Disposable). No internal types leak. Every change to it shows in a committed report. [07 §00; 04 §02; CLAUDE §8] **Adapt:** `@speakkit/protocol` plus the HTTP routes are Speak Kit's public API; snapshot the exported names and route table in a test so a change is visible in review.
- **X2** A new API starts in a proposed tier: used by a first-party consumer and covered by a conformance test before it is documented as public. [08 §11; CLAUDE §8] **Adapt:** a new `/v1/*` route ships with its client and an HTTP-level test.
- **X3** Two version axes: the app version (semver) and the API version (an integer that changes only for breaking changes). The host supports N and N-1 for at least 12 months. Deprecations are marked in types and warn once. [07 §10] **Adapt:** `API_VERSION` and the `version-mismatch` error exist; state the N-1 rule for extension/app skew.
- **X4** A manifest declares its app range, API version, OS list and permissions; compatibility is checked at install and at every load; an incompatible extension is disabled with a reason. [07 §02, §08, §09] **N/A** (third-party extensions). The MV3 manifest keeps `permissions` minimal and `host_permissions` loopback-only.
- **X5** Permissions are a closed, versioned set checked by a broker keyed on connection identity, never on an id in the payload; consent fingerprint; scopes. [07 §05; CLAUDE §8] **Adapt:** token + Origin/Host checks on the server and the IPC sender check are Speak Kit's broker.
- **X6** Trust tiers T0 to T3, pooled hosts, quarantine, kill list, signing, registry and store, runtime limits per extension, 46 extension points in four SDK stages, modes. [07; 08; 06] **N/A.**
- **X7** Built-ins use only the public API (dogfooding). Default a new feature to an extension and keep core only for what cannot wait on extension code. [07 §11; CLAUDE §23] **N/A**; the transferable form is "the desktop and the extension use the server only through `@speakkit/protocol` types and the documented HTTP routes".

## 6. Performance

- **F1** Every feature ships with three things: a budget, a code guardrail that enforces it at runtime, and a named test that fails CI. A budget missing any of the three is not done. A new feature gets a row in the performance contract before it leaves its flag. [12 §00, §08; PERF; 13 §15; DEC §17.9] **A.**
- **F2** Four enforcement tiers. (1) Lint and static checks block merge. (2) Deterministic counts on shared runners block merge: bundle bytes, process count, commits per action, long tasks under 4x CPU throttle, live timers, queue bounds, bench regressions over 15 %. (3) Absolute ms, MB and CPU budgets run on reference machines as p95 over 20 runs and block release. (4) Runtime guardrails cut off the offending feature, never the user's input. [12 §01; PERF] **Adapt:** Speak Kit's tier 3 is the perf phase of `pnpm e2e` plus `apps/desktop/tests/perf.test.ts` on the dev machine; it must gate the release.
- **F3** A release ships only if the absolute-budget run on its exact commit is green. [12 §01; 01 §07] **A.**
- **F4** Seven never-block invariants hold under a hostile load test. N1 no input handler awaits slow code (**A**). N2 main and host loops stay free: main p99 at most 10 ms, host p99 at most 5 ms (**A**, see A12). N3 background work cannot starve interactive work (**A**, see E11). N4 untrusted UI cannot block the window (**N/A**). N5 events never back-pressure producers (**Adapt**, see E5). N6 store updates do not re-render off-screen rows, commits on a selection change at most visible rows + 3 (**A** for the library list and reader). N7 hidden things cost nothing: 0 % CPU over 60 s unfocused, no timer above 1 Hz (**A**). [12 §02; PERF]
- **F5** Headline budgets are p95, one row per area with the guardrail and the test in the same row. Estimated numbers are marked `[est.]`, calibrated once on the reference machines, then frozen. Loosening a frozen number needs an ADR. [12 §03; PERF; OPM §2.6] **A.**
- **F6** Bundle budgets are asserted on the production build: renderer initial JS at most 600 kB gz, secondary entry at most 150 kB gz. [00 §05; 12 §03] **Adapt:** extension bundles have budgets (`apps/extension/src/budget.test.ts`); add the desktop renderer.
- **F7** Idle: 0 % CPU over 60 s with windows unfocused, no timer faster than 1 Hz, total idle memory with one window at most 350 MB including GPU and network helpers. [12 §03; PERF] **Adapt:** Speak Kit's recorded budget is private bytes under 150 MB and working set under 200 MB with the model unloaded and the window hidden.
- **F8** Static performance lint bans `ipcRenderer.sendSync`, `fs.*Sync` after ready, `execSync`, `Atomics.wait`, `setInterval` under 1,000 ms, `measureElement`, immer in hot reducers and Effect imports in renderer entries. [12 §01; 13 §08, §12; PERF] **Adapt:** ban `*Sync` imports from `node:fs` and `node:child_process` outside startup files, and intervals under 1 s.
- **F9** Renderer CPU work that may exceed 8 ms goes to a Web Worker. No task longer than 50 ms during scrolling or interaction; long tasks are measured by trace under 4x CPU throttle. [13 §12; 12 §03] **A** (the 5,000-paragraph extraction test exists; OCR runs in the renderer).
- **F10** Memory per process is a table of baseline and on-demand processes with caps, measured with `app.getAppMetrics()` and private working set. [12 §04, §06] **A.**
- **F11** Each budget names its measurement tool: Playwright traces, `perf_hooks.monitorEventLoopDelay`, `process.cpuUsage()` deltas, `app.getAppMetrics()`, React Profiler, Vitest bench. [12 §06] **Adapt:** event-loop delay and Vitest bench are missing.
- **F12** A bench regression of more than 15 % against the previous main on the same runner blocks merge. [PERF] **Adapt:** optional; Vitest bench for extraction, sentence splitting and text normalization.
- **F13** A new process, renderer, timer or watcher has a budget line and a CI assertion, and is in a process inventory that CI checks against a packaged run. [12 §08; OPM §4.1] **Adapt:** the inventory is a table in `docs/architecture.md`; the packaged smoke test asserts the process count.
- **F14** Hidden panels and surfaces are unmounted. Listeners, handles and registrations are disposed or scoped. [12 §08; 13 §12] **A.**
- **F15** Interactive work runs on dedicated threads at normal priority. Background work runs on a bounded pool at background priority. They never share threads. Every native loop polls a cancel token at least every 1,000 entries or 10 ms. [10 §06; DEC §13.9] **Adapt:** see E11.

## 7. Coding practices

- **C1** Every rule names the tool that enforces it. A rule without a tool yet still applies; add the tool when you can. [13 §01; CLAUDE header; DEC §17.1] **A.**
- **C2** Warnings fail CI. Every `check:*` script is wired into a workflow. [13 §08; CLAUDE §13] **A.**
- **C3** Lint limits (oxlint through Vite+): `complexity` error above 15 (aim at 10), `max-depth` 4, `max-params` warn above 3, `max-lines-per-function` warn above 50, `no-nested-ternary`, `no-else-return`, `no-lonely-if`, `switch-exhaustiveness-check`, no literal strings in JSX, restricted imports, side-effect imports only in entry files. [DEC §17.6; 13 §08] **A.**
- **C4** The limits are review prompts, not targets. Never split code mechanically to pass one. Suppress with `oxlint-disable-next-line <rule> -- <reason>`; suppressions are counted. `@ts-nocheck` is forbidden. [CLAUDE §11; 13 §09] **A.**
- **C5** Style: guard clauses first, flat happy path, `continue` in loops, more than 3 logical operators become a named boolean or predicate, at most 3 positional parameters (else an options object), whole-word names with units (`timeoutMs`, `sizeBytes`), discriminated unions with exhaustive `switch`, no enums, no decorators, no constructor parameter properties. [13 §08; DEC §17.6] **A.**
- **C6** Files stay under about 300 lines and services under 8 dependencies. A feature above about 30 files or 6,000 lines gets a split review by responsibility. Split inside the feature; never create a thin new feature to pass a limit. [13 §02; DEC §17.2] **A.**
- **C7** Ratchets are shrink-only baselines: a new violation fails and a stale baseline entry also fails. They cover file length, suppressions, files over 300 lines, service dependency count and the size of CLAUDE.md. [13 §09; OPM §4.1] **A.**
- **C8** A feature's interface file opens with a 3 to 5 line header (what it does, what it does not do, `@area`), then types and catchable errors with TSDoc giving behaviour, units, errors, cancellation, and who calls handlers. No logic, no re-export of another feature. [13 §02; PROP §2; DEC §17.2] **Adapt:** `index.ts` per feature: header and named exports only, no `export *`.
- **C9** Deletion test: every new file, service, wrapper or feature must hide more than it adds. If deleting it would only move the code into callers it earns its place; if callers would be unaffected it is a pass-through and fails. [13 §02; DESLOP; DEC §17.11] **A.**
- **C10** One concept, one place. A domain rule (name validation, path normalization, ordering, selection) lives in one module. A second implementation across a process boundary is a bug. [13 §02; DEC §17.2, C36] **A.**
- **C11** A service, port or interface is created only at a seam: a feature's exported surface or a system boundary that tests fake. One adapter is a hypothetical seam; two make it real. Otherwise write a plain function. [13 §02; DESLOP] **A.**
- **C12** No import side effects and no global registries. [13 §02; 04 §05] **A.**
- **C13** For a new or breaking interface, write the interface file with TSDoc and the tests at the interface first, then the implementation. For a breaking change sketch two designs and pick one. [13 §02; PROP §2, §5] **A.**
- **C14** Navigation docs are generated, not written: `docs/MODULES.md` (area, purpose, imports, imported-by, export count; no line counts, so branches do not conflict) and `docs/LAYERS.md`. CI fails when the committed copy differs from the generated one. [DEC §17.2, §17.6; PROP §5] **A.**
- **C15** Comments say what the code cannot: TSDoc on every interface export, the why next to non-obvious code (not only in the commit message), `see DECISIONS §N` for decisions. No comment that repeats code, no commented-out code, no TODO without an issue number, no debug logs. [CLAUDE §11; DEC §17.11] **A.**

[13 §05; DEC §17.7; CLAUDE §3] **N/A:** Speak Kit does not use Effect. The transferable parts are C9 to C11 and R4.

## 9. Errors

- **R1** Errors are part of a module's interface: each error a caller must handle makes the module shallower. Handle them in this order: define out, mask low, aggregate, treat bugs as defects, expose what users act on. [13 §06; DEC §17.10] **A.**
- **R2** Define out. Where callers would not act on an error, give the operation semantics with no error case: ensure-style calls, deleting something already gone, cancel or dispose of something finished or unknown, and renaming to a byte-identical name all succeed as no-ops. An already-gone entry in a batch is reported as `skipped`. Selection is never null; range requests clamp. [DEC §17.10 rule 1] **A.**
- **R3** Mask low. Retry short transient errors at most 3 times within 500 ms, inside the request deadline, cancellable, never per entry in an enumeration and never on the dispatch thread. After 3 items in a row exhaust their retries on one resource, fail the rest fast. [DEC §17.10 rule 2] **Adapt:** model download, sidecar install and URL import are the places that may retry; each needs a bound.
- **R4** Aggregate. One handler per request at the rpc edge turns the outcome into a reply: typed failure to its code and arguments, interruption to `Cancelled`, deadline to `DeadlineExceeded`, defect to `Internal` logged with the full cause. One report per batch (done, skipped, failed as plain records). One UI port maps code and arguments to localized text; components never format errors. Each error is logged once, at the edge. [DEC §17.10 rule 3] **A.**
- **R5** Defects for bugs. Impossible states and broken frames between our own processes are defects. Input from outside the trust boundary (HTTP bodies, IPC arguments, settings files, deep links, imported documents) is validated there and fails as a typed error, never as a defect. [DEC §17.10 rule 4] **A.**
- **R6** Corrupt derived state (caches, indexes) is discarded and rebuilt through the normal path. Corrupt user data is moved aside as `*.bad` and the user is told; it is never discarded silently. [DEC §17.10 rule 4, X8] **A.**
- **R7** Expose what users act on; never mask, silently retry or swallow `PermissionDenied`, `PathTooLong`, `VolumeOffline`, `DiskFull`, `InUse`, `NotFound`, `InvalidName` or copy conflicts. [DEC §17.10 rule 5] **Adapt:** Speak Kit's equivalents are `app-not-running`, `token-rejected`, `engine-not-ready`, `page-unreadable`, `file-access`, `busy` and `clip-rejected`.
- **R8** A typed error exists only if a caller handles it differently. It is a tagged class named by condition, carries a code and arguments, never user text, and is not re-wrapped per layer. [DEC §17.10; CLAUDE §4] **A.**
- **R9** The error-code enum is closed and defined next to the list of places to update when a code is added (mapping, `error.<code>` text key, docs, golden frames). Replies carry code and arguments, never text. [02 §06 rule 7; DEC §17.10] **Adapt:** server error bodies carry a `message`; keep it as a diagnostic and never display it.
- **R10** Catch-alls (`catch`, `.catch(() => {})`) appear only in entries, supervisors and the edge file. Nothing swallows an error to turn a test green. [CLAUDE §4, §18; DEC §17.10] **A:** a best-effort cleanup is allowed with a one-line why.
- **R11** Cancellation is an `AbortError`. A rejection from the rpc layer carries `{ code, args }`. Renderer effect handlers dispatch `<feature>/failed` with the code and reducers store the code, not a message. [DEC §17.10; 13 §07] **A.**
- **R12** Deadlines by call class: providers 150 ms per batch, menus 500 ms, preview 3 s, any other call 8 s, then `DeadlineExceeded`. A platform without a feature returns `NotSupportedOnPlatform` and never throws into the UI. [13 §07; 07 §07] **Adapt:** define Speak Kit's classes (the health check's 2 s exists).
- **R13** Every tagged error in an interface is produced by at least one test through that interface, with a fault injected at a system boundary. [DEC §17.10 tests] **A.**
- **R14** Settings files keep the last good value on a parse error, show a status item with line and column, never reset to defaults silently, migrate legacy keys on load from a migration list kept from day one, and heal hand-edited duplicates without deleting user entries. [REF zed 3.8; files 5.9] **A.**
- **R15** Persistence has one writer and atomic writes. On a corrupt open the file is renamed `*.corrupt-<timestamp>` and recreated. Applied-migration hashes are stored and a mismatch fails dev builds. [REF zed 3.9] **Adapt** to JSON files (library index, config, `engine.json`, voice index) with a `schemaVersion`.
- **R16** Per-extension error aggregation and extension health. [DEC §17.10 rule 3] **N/A.**

## 14. Review checklist

One list a reviewer ticks for every change. Each line points at the rule it enforces. A reviewer gets the brief, the diff and the gate results, never the implementer's transcript, and writes findings before reading the implementer's report. [OPM §6.5; 16 §01]

- [ ] Does what the brief asks and nothing outside its scope; removes no user-visible behaviour the brief does not mention. [CLAUDE §19]
- [ ] Matches the cited decisions and ADRs; introduces no new dependency, process, protocol or pattern (D3, P15, A11).
- [ ] Layers, boundaries, platform checks, strings, logical CSS and disposables follow CLAUDE.md (P1 to P12, A6, L1, L10, C17).
- [ ] Tests exercise behaviour through the public interface with literal expected values; no redundant tests; no expected value changed unless the brief says behaviour changed (T1 to T4, T22).
- [ ] Every integrity flag is answered: skipped tests, loosened budgets, changed baselines, hollow assertions, test-context branches (T22, T23, T24, C25).
- [ ] Nothing on the input path awaits slow code, and no per-row or per-item IPC call exists (A1, F4, A5).
- [ ] New process, window, timer, watcher or worker has a budget line and a CI assertion (F13).
- [ ] UI matches its design frame; the frame id is in the commit message; a screenshot is attached (A10, D18, D20).
- [ ] No hardcoded strings, physical `left` or `right`, hand-edited generated tokens, or network call before first paint; any new network call is on the privacy page; logs hash paths at `info` (L1, L10, P4, S14, S17).
- [ ] Deep-link and IPC handlers validate arguments and confirm before any operation (S5, S8).
- [ ] The report states what was not verified (T25, D19).
- [ ] The change adds no abstraction, option, wrapper, config key, extension point or helper the brief did not ask for (G7, C9, C11).
- [ ] Every external API used exists in the pinned version; the lookup is visible or the API is already used in the repo (D9, C21).
- [ ] Design block: deletion test passes for every new file, service, wrapper or feature; no pass-through; the interface is small and common use needs no rare options; one rule lives in one place; errors follow the error model; names use glossary terms; interface exports carry TSDoc; an existing example is followed or the new pattern is explained (C9 to C11, R1 to R13, N1, N2, C8).
- [ ] Anti-slop list is clear (G23).
- [ ] No dead code, debug logs or TODOs without an issue number (C15, C23).
- [ ] A fresh reader finds the change from `docs/MODULES.md` plus the interface files in two reads (C14).
- [ ] Definition of done holds: `vp check` and `vp test` pass; UI state change is a reducer action with a Node test; new listeners and handles are disposed; new feature has its `docs/perf.md` row; brief has the prior-art verdict; copied code carries an "Adapted from" header and a notices entry (U1, C17, F1, C18, C19).

## 15. Agent workflow and de-slop

- **G1** One task per session. A task is under one day and about 400 changed lines excluding generated files; a branch lives under one day and is rebased on main before review. After a context compaction, re-read the brief and the decision sections it cites. [CLAUDE §19; 16 §09; OPM §7.1] **A.**
- **G2** Roles are separate runs with their own context, and no role approves its own work. Planner writes briefs; implementer writes code, tests and the retrospective; reviewer works in a fresh context. [16 §01, §02; OPM §1] **Adapt:** one implementer run and one separate reviewer run per work package.
- **G3** A task brief has: goal (one sentence), scope (folders it may touch), design frame, decision sections and ADRs, protected paths touched, `Behaviour change:` line with its source, acceptance tests by name and budget assertions, what is not in scope, prior-art verdict, `load:` field, `class:` field, working copy, and the report format. [OPM §6.4; CLAUDE §17, §23] **A.**
- **G4** Work in your own worktree on branch `agent/<task-id>`. Never check out, reset or commit on main. Start test suites in the background and keep working. One Playwright process at a time. [CLAUDE §19] **A.**
- **G5** Stay inside the brief's scope. Remove only what your change made dead or turned into a pass-through. Older problems become issues or de-slop cards, so parallel branches do not collide. [CLAUDE §19; 13 §11] **A.**
- **G6** After two review rounds, the planner re-scopes or parks the task. After two identical failures in a row, stop, park the task with the error in the brief, and take another task. Every command has a timeout. [16 §09; CLAUDE §19] **A.**
- **G7** Add no abstraction, option, wrapper, config key, extension point or generic helper the brief does not ask for. One caller means no abstraction. [CLAUDE §19] **A.**
- **G8** A red main is fixed before any other merge: fix forward or revert; never rewrite main's history. [CLAUDE §19; 16 §09] **A.**
- **G9** Ask the user only for: changing a decided item, adding or replacing a shipped dependency, language, framework or process type, loosening a frozen budget, freezing or bumping a public API version, promoting a build or a rollout, money, accounts, legal text or anything that sends data off the machine, destroying unmerged work or user data, design gaps, accepted screenshot baselines, and loosening a gate. Everything else: decide within the records, pass the gates, report it. Ask as one numbered list, recommended answer first, worded so "yes" accepts it; park the affected task meanwhile. [CLAUDE §22; 16 §09] **A.**
- **G10** Protected paths need a second reviewer with an architect's brief ("start from reject"): the protocol package, process entries, dependency files, gate and CI configuration, the decision records, CLAUDE.md. [16 §05; OPM §4.2] **Adapt:** Speak Kit's list is `packages/protocol`, `apps/*/src/main/index.ts` and the extension manifest, `package.json` and `pnpm-workspace.yaml`, `vite.config.ts` lint rules, `.github/workflows`, `docs/decisions`, `code/CLAUDE.md`.
- **G11** Fitness functions in CI, deny-by-default: layers and imports; dependency allowlist; process inventory; ADR sync (a decision-record change needs an ADR in the same merge); protected-paths trailers; gate canaries; lockfile and vendored-code ratchets. [16 §05; OPM §4.1] **Adapt:** see the refactor plan WP-1 for the subset worth building.
- **G12** Integrity gate on every branch: `.skip`, `.only`, raised retries, `@ts-nocheck` fail; a grown ratchet baseline or a loosened budget fails without an ADR; changed screenshot baselines fail unless the user approved; a changed expected value or removed assertion needs the reviewer to confirm the brief says behaviour changed. [16 §06; OPM §4.5] **A.**
- **G13** Prior art before building (C18), licence rules (C19) and performance as a selection criterion (C20). [CLAUDE §17] **A.**
- **G14** New library or tool: intake note, screen, spike outside the repo, ADR, decide, adopt behind a flag where possible, review within 8 weeks. Nothing is adopted from one run, one blog post or because it is newer. [16 §07; OPM §4.3] **A.**
- **G15** Evidence pack: a UI change carries before and after screenshots (light and dark) and a recording when motion or a flow changes; an engine change carries the benchmark delta. Missing evidence blocks review. [CLAUDE §23; INT software-factory] **A.**
- **G16** Human attention by risk: trivial changes (docs, lint, refactors with unchanged screenshots) merge on green; routine changes merge when reviewers converge and appear in the digest; changes under risk paths wait for the user's plain-English approval; architecture changes need an ADR first. [CLAUDE §23] **Adapt:** Speak Kit risk paths: wire protocol and server auth, IPC contract, updater, library storage and migrations, process spawn, extension permissions.
- **G17** A bug the user finds is captured as an issue (build, frame, steps), classified (bug, design question, decision change), gets a failing test, then a fix; the retrospective asks why no gate caught it and adds a test, rubric item, gate or skill step. [16 §08; OPM §5] **A.**
- **G18** After every task write a five-line retrospective: friction, cause, owning surface, lesson or "none". If the friction matches a lesson, add the task id; else create a candidate lesson. [CLAUDE §20; OPM §6.5] **Adapt:** one line per task in the task report.
- **G19** At each milestone, run a cleanup task with its own brief that removes what the milestone made dead and files older problems as issues. [CLAUDE §23] **A.**
- **G20** Limits: 4 implementers in parallel, 6 agents in total (more needs the user's yes with a cost estimate), a kill switch file, 80 % of the token budget lets only in-flight tasks finish. [16 §09; OPM §7.1] **Adapt:** Speak Kit's rule is "say the rough cost and ask before more than about 6 agents".
- **G21** Read-only research inside a task runs in a sub-agent with fresh context that returns a short summary. [OPM §1] **A.**
- **G22** The de-slop pass. Terms (use exactly these): module, interface, depth, seam, adapter, locality, leverage. One adapter is a hypothetical seam; two make it real. Steps: (1) scope to the area named, else the 5 most-changed features in the last 14 days; skip features with an open task or unmerged branch; (2) read `docs/MODULES.md`, those features' interface files, the decisions and ADRs that touch them, and earlier rejections; (3) explore read-only and note friction: understanding one concept needs hops across many small modules, an interface almost as big as what it hides, pass-through services or wrappers, the same rule in two places (above all across a process boundary), pure functions extracted for tests while bugs sit in the wiring, the anti-slop list; (4) apply the deletion test to each suspect; (5) write one card per candidate with files, problem (term plus red flag), change, gain in locality, leverage and tests, and strength (Strong, Worth exploring, Speculative), with no new interfaces yet; (6) route: inside one feature with no interface change becomes a task; an interface change or merging features goes to the architect reviewer with two sketches; (7) each accepted card becomes a task with tests at the target seam first and `Behaviour change: none`; (8) a card rejected for a lasting reason gets a `rejected:` line so the next pass skips it. At most 3 cards become tasks per pass. Run weekly once there are 10 or more feature modules, and on request. [DESLOP; 16 §02; DEC §17.11] **A:** Speak Kit has 8 or more feature folders in the extension alone; run once after the refactor.
- **G23** Anti-slop list: pass-throughs; speculative generality; a second implementation of an existing rule; defensive checks for impossible states, swallowing or catch-all `catch`, wrapping per layer; comments that repeat code, commented-out code, TODOs without an issue; vague exported names (`data`, `info`, `item`, `result`, `*Manager`, `*Helper`, `*Util`) or terms that differ from the glossary; unused exports; tuples or generic containers in interfaces; getters, setters or internal maps exposed through an interface. [DEC §17.11] **A.**
- **G24** Design twice: for a new or breaking interface, wire message or public API, sketch two designs, pick one and say why before code. The brief's `api-change` field is none, additive or breaking. [13 §11; DEC §17.11; PROP §2] **A.**
- **G25** The implementer reads `docs/MODULES.md` first, then each dependency's interface file; opens a dependency's internals only when the task changes it; finds an existing example and follows it. [DEC §17.11] **A.**
- **G26** Agents that read a copyleft repository describe behaviour in words; a different agent that has not read that repository writes the code. [13 §13; DEC Q35] **A.**
- **G27** Known limit to keep in mind: agents reviewing agents share blind spots; mechanical gates, canaries, trap tasks and the user's manual testing are the checks. A gate that checks structure cannot catch intent. [16 §10; OPM §8] **A.**

## 16. Findings from the reference studies that transfer

The notes in `references/*.md` study other products (file managers, editors, a diff viewer, a terminal). Most findings are about file watching, Windows shell integration, listings and search, which do not apply to Speak Kit. These transfer.

- **V1** A call that can block on an unreachable resource gets a deadline, and the caller abandons it and reports the condition; the blocked worker is not reused for interactive work. [REF files 5 "SMB guard"; REF strata 3] **Adapt:** `execFile` detection has 8 s, the health check 2 s; add deadlines to the sidecar `synth` request, installer steps and model download stalls (see E9, F23).
- **V2** A hung source must not occupy every interactive slot: requests carry a ticket keyed by source and a stalled ticket (no heartbeat for 2 s) marks the lane stalled, so new interactive requests fail fast with a "busy" answer. [REF strata 3] **Adapt:** a stalled Chatterbox sidecar must not hold both synthesis slots; heartbeat from the sidecar progress lines and fail the stream with `engine-not-ready` or `synthesis-failed`.
- **V3** A document is a list of blocks keyed by a hash of their content; parse once in a worker, sanitize only unseen keys, lazily and in slices of at most 8 ms, visible blocks first. [REF backtickle 3] **Adapt:** document import parses in a worker (A2); the reader sanitizes or renders lazily by block.
- **V4** Measure what the user waits for with named marks shared across processes, and assert the marks in CI (see A17). [REF vscode 3.8] **Adapt.**
- **V5** Persist a cached index keyed by the inputs that invalidate it (directory mtime, app build, locale, host API version), and rescan at `eventually` to confirm it. [REF vscode 3] **Adapt:** the library index, voice index and engine list; key them by app version and schema version.
- **V6** Settings files: last good value on a parse error, status item with line and column, migrate legacy keys from a migration list kept from day one. [REF zed 3.8, REF files 5.9] **A** (see R14).
- **V7** A watcher event is a hint: fingerprint cheaply and show a "changed on disk, refresh" bar instead of refetching. [REF diffity 3] **N/A:** Speak Kit watches no files except the clipboard poll.
- **V8** Keybinding precedence (user over extension over core, then context depth, then later wins), chords with a 1 s timeout, `null` unbinds, AltGr rule. [REF vscode 3.4, REF zed 3.3; ADR 0007] **N/A** for Chrome `commands` (Chrome resolves them); **A** for desktop global shortcuts only as far as L9.
