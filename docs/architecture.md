# SpeakKit architecture (v1, extension-first)

Contract source of truth: `code/packages/protocol/src` (types, frame codec, settings). Change it only with a note in this file.
Design source of truth: `designs/screens/<ID>.png` + `designs/manifest.json` (ID, title, note) + tokens in `designs/gen/kit.ts` (LIGHT/DARK, blue accent #2457F5, Tabler icons).
Priority: the Chrome extension must be fully working with the local server. The desktop app is a thin companion in v1 (library and reader screens D-F are v1.1).

## Stack (do not swap)
Electron, React, TypeScript, **Vite+ (`vp`)** for dev/build/test/lint/format, **tsrs** for type checks (`pnpm exec tsrs --noEmit -p <pkg>`; if tsrs misbehaves on something, fall back to `tsc` and note it), pnpm workspaces, `kokoro-js` + `onnxruntime-node` for speech. Tests import from `vite-plus/test`. Performance is a requirement: no framework in content scripts (plain TS + Shadow DOM), CSS Custom Highlight API for highlighting (no DOM mutation), engine in a worker thread, stream per sentence, one cached AudioContext.

## Layout (`code/`)
| Path | Owner | What |
|---|---|---|
| `packages/protocol` | done | API types, frame codec, extension messages, settings schema |
| `packages/engine` | engine-server | `TtsEngine` interface, `KokoroEngine` (model host in a child process by default or a worker thread, onnxruntime-node, uint8, lazy load, idle unload, model download with progress), `FakeEngine` (deterministic tones, configurable latency, for tests) |
| `packages/server` | engine-server | loopback HTTP server (`node:http`, no framework), token store, Origin/Host checks, `/v1/*`, standalone CLI |
| `apps/extension` | ext-core + ext-content + ext-ui | MV3 extension, output `apps/extension/dist` |
| `apps/desktop` | desktop | Electron + React companion |
| `e2e` | e2e / visual agents | Playwright suites, fixture pages |

## Server (packages/server)
- `createServer({ engine, dataDir, port, host = "127.0.0.1", version, token? })` returns `{ listen(), close(), port, token }`.
- Token: 32 random bytes hex, persisted in `<dataDir>/token`, override with `token` option or env `SPEAKKIT_TOKEN`. Compare with `timingSafeEqual`.
- Reject (403) any request whose `Origin` is not absent or `chrome-extension://*`, and any `Host` other than `127.0.0.1:<port>` / `localhost:<port>`. CORS: answer preflight for chrome-extension origins only.
- `/v1/speak`: validate body (sentences 1..500, each <= 2000 chars, speed 0.5..3, voice known). Stream frames per `frames.ts` with `Transfer-Encoding: chunked`, flush after every frame, stop work when the socket closes. Synthesis runs in the engine worker, never on the HTTP thread. Effective model speed = `min(speed, 2)`.
- Standalone CLI `code/packages/server/src/cli.ts`: env `SPEAKKIT_PORT` (default 47615), `SPEAKKIT_DATA_DIR`, `SPEAKKIT_ENGINE=kokoro|fake`, prints one JSON line `{port, token}` when listening. Env and options are parsed with valibot (`src/config.ts`); a malformed value exits with code 1 and `invalid environment: <VAR>: <why>`. Other variables: `SPEAKKIT_IDLE_MS` (0 never), `SPEAKKIT_LOAD_AT_START=1`, `SPEAKKIT_MAX_STREAMS` (2), `SPEAKKIT_MAX_QUEUE` (8), `SPEAKKIT_DTYPE`, `SPEAKKIT_DEVICE`, `SPEAKKIT_THREADS`, `SPEAKKIT_WORKER_URL` (path or file URL of the worker), fake engine: `SPEAKKIT_FAKE_STATE|LATENCY_MS|LOAD_MS|FAIL_ON`.
- Extra `createServer` options: `idleUnloadMs`, `loadAtStart`, `maxStreams`, `maxQueue`. The returned object also has `setIdleUnloadMs(ms)` and `setOnBattery(bool)` (the desktop app calls them when the setting or the power source changes).
- Errors: every HTTP error has the body `{ "error": { "code", "message" } }`. Codes: `invalid-request` (400 bad JSON or a field out of range, 413 body over 2 MB), `token-rejected` (401), `forbidden` (403 bad Origin or Host), `not-found` (404), `method-not-allowed` (405), `busy` (429), `internal` (500).
- `/v1/speak` failure modes: problems found before streaming (auth, validation, 429) are HTTP errors. After validation the response is always `200` with frames; anything that goes wrong later arrives as one `error` frame (`engine-not-ready` when the model is missing, downloading or failed to load, `synthesis-failed` when a sentence fails) and the stream ends. A stream the client cancels or that another request replaced ends without a `done` frame.
- Endpoints added for the lifecycle: `POST /v1/engine/warm` (token; answers `202 {"state"}` at once; starts loading when the state is `unloaded` or `error`, refreshes the idle timer when `ready`, does nothing while `missing` or `downloading` because downloads are explicit) and `POST /v1/engine/hold` (token; body `{"ms": 0..3600000}`; `204`; keeps a ready model loaded for at least that long from now, 0 clears; the extension sends 600000 when playback is paused and 0 on resume, because the server cannot see pause).
- Concurrency: at most `maxStreams` (2) `/v1/speak` streams synthesize at once, the next `maxQueue` (8) wait FIFO (no bytes are sent until a slot is free), beyond that `429 busy` with `Retry-After: 1`. Header `X-SpeakKit-Replace: <id>` (1 to 64 of letters, digits, `. _ : -`) makes the request cancel the earlier running or queued streams that were sent with the same id, so each tab passes its own id and a seek or speed change in one tab does not cancel another tab's reading, and does not wait behind the old stream. `1` keeps the legacy meaning (every earlier stream of the token, grouped or not) and a stream sent with `1` belongs to no group; any other value is `400 invalid-request`. The sentence the worker is already synthesizing cannot be interrupted, so the new request still waits for that one sentence (about 1 s).
- Build: `pnpm exec vp pack` in `packages/engine` emits `dist/index.js` and `dist/worker.js`; in `packages/server` it emits `dist/index.js`, `dist/cli.js` and `dist/worker.js` (workspace packages and valibot bundled; `kokoro-js` and onnxruntime stay external and must be installed next to the packaged app). `KokoroEngine` looks for `worker.js` next to the module that contains it; when that is not true (Electron asar, another bundler) pass `workerUrl` (a file URL of the real, unpacked `worker.js`; worker threads cannot run from inside an asar archive). Tested by `tests/pack.test.ts`, which packs and runs `node dist/cli.js`.
- Model cache: `<dataDir>/models` (override `SPEAKKIT_MODELS_DIR`; tests share `D:/workspaces/speak-it/code/.cache/models`). `onnx-community/Kokoro-82M-v1.0-ONNX`, dtype `uint8` (not `q8`: in transformers.js `q8` loads `model_quantized.onnx`, which is about 4 times slower than `model_uint8.onnx` on this CPU, 3.9 s against 0.9 to 1.0 s to the first frame, see perf.md), device `cpu`. Health reports `downloading` with progress 0..1.
- Performance targets on this machine (RTX 4080 laptop, CPU path): first audio frame for a 12-word sentence < 1.2 s warm, real-time factor < 0.35, idle RSS < 700 MB. Measure and record in `docs/perf.md`.

### Wire schemas
`@speakkit/protocol` holds the interfaces and, next to them (`schemas.ts`), the valibot schemas for what the server answers (health, voice list, engine list, export job, error body), typed `GenericSchema<unknown, T>` so the compiler fails when they drift. The extension and the desktop app parse responses with them. `format.ts` holds `clock(ms)`. The protocol package is `sideEffects: false` so a script that imports only types or constants does not pull valibot in.

### Server code layout (v0.2.0)
`server.ts` only wires: `http.ts` (guard for Host and Origin, bearer check, JSON helpers, `HttpError`), `router.ts` (route table, 404 and 405), `routes/{status,speak,engines,voices,export}.ts` (one table of routes each), `stream-queue.ts` (synthesis slots shared by speak streams and exports, `X-SpeakKit-Replace` groups), `render.ts` (normalize, synthesize), `engines.ts` (registry), `export.ts` (jobs). `allowedExtensions` / `SPEAKKIT_EXTENSION_IDS` limit which `chrome-extension://<id>` origins may call; unset allows any extension that has the token.

## Engines, cloning and export (packages/engine, packages/server)
- **Engines**: `kokoro` (default, always present) and optional `chatterbox` (`ChatterboxEngine`, Python sidecar, NVIDIA GPU with 4 GB+, Python 3.10 to 3.12 or uv, decision in the ADR). Only the active engine is ever loaded: `POST /v1/engines/select` cancels running streams and exports, persists the choice in `<dataDir>/engine.json`, and waits for the previous engine to unload (`release()`); it does not load the new one (lazy). A saved choice that cannot run now (GPU or install gone) falls back to Kokoro without being forgotten. `/v1/health`, `/v1/voices`, `/v1/engine/warm` and `/v1/engine/hold` act on the active engine.
- **Engine states** (additive to `EngineState`): `unavailable` (cannot run here, `reason` `no-gpu` | `python-missing`), `missing` with `reason: "not-installed"` (installable), `installing` (venv + pip, progress approximate), `downloading` (weights, from the sidecar), then the usual `unloaded -> loading -> ready`. `GET /v1/engines` returns `{active, engines: [{id, name, state, progress?, detail?, reason?, optional, cloning, gpu?}]}`; `POST /v1/engines/chatterbox/install` answers 202 with the list (409 `engine-unavailable` when it cannot run); a failed install returns to `missing` with the error in `detail`; `DELETE /v1/engines/chatterbox` deletes the environment and weights (cloned voices stay) and falls back to Kokoro. The desktop creates the engine with `createChatterbox(dataDir)` (exported by `@speakkit/server`) and passes it as `createServer({ chatterbox })`; for a packed app pass `sidecarScript` (the path of the unpacked `chatterbox_sidecar.py`; env `SPEAKKIT_CHATTERBOX_SCRIPT` for the CLI). `SPEAKKIT_CHATTERBOX=off` disables it in the CLI.
- **Sidecar protocol** (`packages/engine/sidecar/chatterbox_sidecar.py`): JSON lines. In `{op:"synth", id, text, reference}` and `{op:"abort", id}` (stops that request between sampled tokens, no reply; the engine sends it when the caller aborts); the sidecar analyses a reference clip once and reuses it while the same path is requested; out `{kind: "progress"|"ready"|"fatal"|"audio"|"error", ...}` with int16 PCM in base64. Stray stdout lines are ignored; a crash marks the engine `unloaded` and the next request restarts it.
- **Voice cloning**: `POST /v1/voices/clone` with `{name, consent: true, audio: <base64 WAV>, gender?}` (body limit 40 MB, any PCM or float WAV, stereo mixed down). Failing checks (`CloneCheck` ids `length` 5 to 30 s, `sample-rate` >= 16 kHz, `loudness`, `silence` <= 50%, `noise` SNR estimate >= 15 dB) give `422 clip-rejected` with `checks` (the per-criterion rows of G7); a non-WAV file is `422` with `not a WAV file`; missing consent is `400`; Chatterbox not installed or unavailable is `409 engine-unavailable` (G14). Success is `201 ClonedVoice`. `GET /v1/voices/cloned` lists them, `DELETE /v1/voices/<id>` removes one (204/404). Cloned voices are files in `<dataDir>/voices` and appear in `/v1/voices` (with `cloned: true`) while Chatterbox is active. Cloning does not need the model loaded. The speaker's gender is not detected; it defaults to `female` unless the client sends it.
- **Export**: `POST /v1/export {sentences, voice, speed <= 2, gapMs?}` returns 202 `ExportJob`; the job takes a normal synthesis slot and writes `<dataDir>/exports/<id>.wav` as sentences finish. `GET /v1/export/<id>` returns `{state: running|done|cancelled|error, done, total, durationMs, error?}`, `GET /v1/export/<id>/audio` streams the finished WAV (409 until done), `DELETE` cancels and removes. At most 16 jobs; finished jobs are swept after 1 h and all files at server start and stop. MP3 encoding is the desktop's job.
- **Text normalization**: `normalizeText` (engine package) runs in the server before every synthesis (speak and export): URLs and e-mail addresses are spoken as host or words, emoji removed, `e.g.`/`i.e.`/`vs.`/`approx.` expanded, scaled and prefix currency (`$5M`, `€20`) and units (`5 km`) spelled out; for engines with `needsNumberWords` (Chatterbox) digits are spelled too. Measurements in perf.md.

## Extension runtime
```
page (content script)  <-- chrome.runtime msgs -->  service worker  <-- msgs -->  offscreen document (player)
   Shadow-DOM UI, extraction, highlight                router, settings, queue,         fetch stream -> FrameDecoder ->
                                                       menus, commands, offscreen        Web Audio gapless scheduling
popup / options / side panel talk to the service worker only (ContentToBg / PlayerCommand) and listen for broadcasts.
```
- Network only from the offscreen document (extension origin, `host_permissions: http://127.0.0.1/*`). Content scripts never fetch the server.
- The offscreen document owns the player state machine (`PlayerState`) and the queue; it posts `PlayerState` on every change and `SentenceStart` on each sentence boundary. The service worker relays both to the tab named in `PlayerState.tabId` and to extension pages.
- Playback: decode frames to `AudioBuffer`, schedule back to back on one `AudioContext` (`start(t)` chaining, lookahead 2 sentences), `playbackRate = max(1, speed / 2)` for speeds above 2. Seeking aborts the stream (`AbortController`) and re-requests from the target sentence. Changing speed or voice does the same from the current sentence.
- Skip +-10 s: pick the sentence whose estimated start is nearest `elapsed +- 10 s` (durations known for synthesized sentences, estimated at 15 chars/s/speed otherwise).
- Word highlight: content script gets `SentenceStart`, splits the sentence into words and advances by character weight over `durationMs / playbackRate`. Sentence highlight is exact.
- Test hook: when `localStorage["speakkit.test"]` or the build flag `__TEST__` is set, the offscreen document exposes `window.__speakkit = { state, framesReceived, scheduledMs, rms() }` (AnalyserNode RMS) so e2e can prove sound is produced without audio hardware.
- Errors map to `ErrorCode`: connection refused -> `app-not-running`; 401 -> `token-rejected`; health engine not ready -> `engine-not-ready`; restricted URL (chrome://, Web Store, PDF viewer without access) -> `page-unreadable`; file:// without permission -> `file-access`.
- Storage: settings in `chrome.storage.sync` (`SETTINGS_KEY`), token in `chrome.storage.local` (`TOKEN_KEY`). Pairing UI: options page "Pairing token" field + "Test connection" (`/v1/auth/check`, `/v1/health`).
- Shortcuts (manifest `commands`): `Ctrl+Shift+S` read selection / page, `Ctrl+Shift+Y` play-pause (Ctrl+Shift+P and Alt+Shift+P are never assigned by Chrome here, checked with chrome.commands.getAll), `Ctrl+Shift+X` stop. In-page keys while reading: Right/Left next/previous paragraph, Up/Down speed, Esc close dock.

## Content script (`apps/extension/src/content`)
- `extract.ts`: find the main content root (article/main/role=main, else densest text block), collect block elements (p, li, h1-h6, blockquote, figcaption optional, td when no better), skip hidden/aria-hidden/nav/aside/footer/header/form/script/style/code (per settings.skip), drop citations `[12]`, speak "link" for long URLs. Output blocks with live `Range`s, split sentences with `Intl.Segmenter("granularity: sentence")`, merge abbreviations ("Dr.", "e.g."), cap sentence length ~300 chars at clause boundaries. Must handle a 5,000-block page in < 50 ms of main-thread work (measure).
- `highlight.ts`: `CSS.highlights` with names `speakkit-sentence` and `speakkit-word`, stylesheet injected once. Auto-scroll keeps the current sentence in view unless the user scrolled away, then show the "Back to current" pill.
- `ui/`: closed Shadow DOM host, Tabler icons inlined as SVG strings, no React. Components per designs: selection bubble (B1), paragraph gutter play button (B2), edge launcher vertical pill (B17-B21), floating dock (B4-B9, B15-B16), toast (B13), back-to-current (B14). Respect `Settings.show`, `Settings.launcher`, per-site rules. Content script injects lazily: tiny bootstrap on `document_idle`, heavy UI on first interaction.
- Context menu entries (created in the service worker): "Read selection", "Read from here", "Add to queue" under a SpeakKit parent.

## Popup / options / side panel (React, `apps/extension/src/{popup,options,sidepanel}`)
Pixel-faithful to A1-A15 (popup 380 px wide), C1-C8 + C12 (options), C9-C11 (side panel). Shared tokens in `src/ui/tokens.css` from `designs/gen/kit.ts` (light + dark via `prefers-color-scheme`). States come only from `PlayerState` plus `Health` (poll `/v1/health` through the service worker, cache 3 s).

## Desktop (apps/desktop)
Electron main starts the same `createServer` in-process (engine in its worker thread), tray icon (open / quit), `requestSingleInstanceLock`, window with React UI: first-run (welcome, engine download with progress, pair browser: token reveal/copy and the extension install hint), settings basics (port, launch at login), voices list with preview. Library/reader are v1.1.

### Desktop main process layout (v0.2.0)
`main/index.ts` is boot only. `main-window.ts` (the window, hide-to-tray, destroy after 30 s hidden, the quitting flag), `server-lifecycle.ts` (`ServerRuntime`: engines, server, restart, health polling only while the window is visible), `handlers.ts` (the shell's IPC methods), `desktop.ts` (reading, exports, updates, tray, shortcuts and their handlers), `ipc-register.ts` (sender check + valibot arguments, used by the app and the library), `secure-window.ts` (the one factory every window goes through: sandbox, no navigation, no new windows), `test-env.ts` (test-only switches, ignored when packaged). The renderer never imports from `main/`; wire contracts live in `src/shared` (lint rule `no-restricted-imports`).

### Extension service worker layout (v0.2.0)
`app/background/index.ts` registers listeners. `router.ts` handles the inbound messages (parsed with `shared/schemas.ts`; the known types come from the schema), `player.ts` (commands to the offscreen player), `offscreen.ts`, `reading.ts` (extract and start a read), `connection.ts` (health cache, app launch), `menus.ts`, `commands.ts`, `state.ts`. The worker is suspended when idle: player state, the last document, the queue and the auto-play choice are mirrored to `chrome.storage.session` and read back on demand.

## Resource lifecycle (models, memory, idle) — requirement, added 2026-11-01
Implemented in `packages/engine/src/lifecycle.ts` (`LifecycleEngine`, base class of `KokoroEngine` and `FakeEngine`) and wired by `packages/server/src/server.ts`. A cold model already on disk starts as `unloaded`; a missing one as `missing` and is fetched by `engine.start()` (the CLI does this at boot), whose path is `missing -> downloading -> loading -> ready` (the download happens inside the load, so there is no separate `unloaded` after it). Details that go beyond the list below: a request that finds the engine `unloaded` or `loading` waits for `ready` (it fails with `engine-not-ready` only for `missing`, `downloading` or a failed load, and a `/v1/speak` retries a failed load); streams mark themselves active so the idle timer only runs between streams; the deadline is `max(last activity + window, hold end)`, the window is `min(window, 1 min)` on battery when it is not "never"; the low-memory check runs every 15 s while idle and needs 30 s of inactivity so a fresh load is not thrown away; an unexpected worker crash turns `ready` into `unloaded` so the next request reloads. The target behavior:
- **States**: `missing -> downloading -> unloaded -> loading -> ready -> unloaded` (add `unloaded` to `EngineState` and `idleUnloadAtMs?` to `Health.engine`; the extension shows "wakes on play" in that state and never treats it as an error).
- **Lazy by default**: starting the server or the desktop app does not load the model (`Load at startup` is an option). First `/v1/speak` loads it. `POST /v1/engine/warm` (token, idempotent, returns immediately) lets the extension load it ahead of the click: call it, debounced, when the popup opens, when the launcher is hovered or opened, and when text is selected. Measure cold load time and report it.
- **Idle unload**: after the last synthesis plus an idle window (default 5 min; options 1, 5, 15 min, never) stop the model host so onnxruntime memory is returned to the OS. Measured: terminating a worker thread leaks about 2.6 MB of native memory per cycle (+124% RSS over 50 cycles), so the host is a child process by default (`isolation: "process"`) and unloading kills it; see perf.md. The packed worker works in both modes. In Electron the process is started with `child_process.fork` (Electron runs it as node), so `workerUrl` must point at an unpacked `worker.js`. Never unload while a stream is active; while playback is paused keep the model for at least 10 min. On battery use 1 min, and unload early when `os.freemem()` falls under 1 GB. Env `SPEAKKIT_IDLE_MS` overrides for tests.
- **One heavy engine at a time**: Chatterbox (later) and Kokoro never sit in RAM together; GPU memory is freed on unload; sidecar processes are killed after idle.
- **Desktop idle cost**: window hidden means no timers or animation (`backgroundThrottling`), renderer paints nothing; target total app RSS when unloaded and hidden < 150 MB.
- **Extension side**: offscreen document is created on first play and closed 60 s after stop; `AudioContext` is suspended on pause and closed when idle; keep only 2 to 3 sentences of decoded audio ahead and drop played buffers; abort the stream on tab close or navigation; content script does no work until first interaction, disconnects observers and clears CSS highlights on stop; the service worker keeps no state outside storage.
- **Budgets to measure and record in `docs/perf.md`**: cold load time, warm time to first audio, RSS ready vs unloaded, share of model memory returned after unload (target >= 80%), 50 load/unload cycles with RSS growth < 5% (no leak), time to first audio when the extension warmed the engine before the click (target equal to warm).
- **Tests**: server tests with `SPEAKKIT_IDLE_MS` small (unload happens, next request reloads, active stream blocks unload, warm endpoint), a memory/leak test (opt-in real model), and e2e that proves popup-open warms the engine.

## Shared player, desktop library and reader (added 2026-11-01)
- `code/packages/player` holds the playback core (`Player`, `soundTouchStretch`, `splitSentences`, `PlayerConfig`, `QueueItem`). The extension offscreen document (`apps/extension/src/app/offscreen/main.ts`) and the desktop reader (`apps/desktop/src/renderer/features/reader`) both construct it; only the `PlayerDeps` differ (extension: chrome messaging and `fetch`; desktop: a `fetch` that goes through the main-process speak proxy). `/v1/speak` re-requests send `X-SpeakKit-Replace: tab-<tabId>` (desktop: `tab-0`).
- Library data: `<userData>/library/library.json` (index, lowdb) and `docs/<id>.json` (blocks) plus `docs/<id>.src` (original bytes, only for PDFs that need OCR). Contract and channels: `apps/desktop/src/main/library/contract.ts` (`window.speakkitLibrary`, validated with valibot in main). Import parsers are pure functions in `main/library/parse/` (text, markdown, html with Readability, pdf with layout, docx, epub); a document is a list of `Block`s (heading, paragraph, quote, list item, optional PDF page).
- Reader: blocks are split into sentences (`buildDoc`), the player reads sentences, highlights use the CSS Custom Highlight API (`sk-sentence`, `sk-word`, `sk-find`); the word is estimated inside the sentence by character weight (no word timings from Kokoro). Progress is saved at most every 3 s and on pause, finish and leave. OCR (pdf.js render + tesseract.js) runs in the renderer only after consent and is lazy loaded.
