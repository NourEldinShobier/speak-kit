# SpeakKit package audit

Date: 2026-11-01. Rule from the user: if a maintained package can do the job, do not build it from scratch.
Scope: read-only audit of `code/`. Nothing under `code/` was edited and no `pnpm add` was run.

## How the numbers were produced
- Versions, licenses, publish dates: `npm view` on 2026-11-01. Weekly downloads: api.npmjs.org, last-week.
- Sizes: throwaway project in the session scratchpad, `esbuild --bundle --minify --format=iife`, gzip -9. esbuild is not Rolldown, so treat sizes as close approximations, not exact. Delta rows subtract a bare React 19 + react-dom `createRoot` bundle (222.8 KB raw / 68.9 KB gz).
- Build-tool trials: WXT 0.21.5 and @crxjs/vite-plugin 3.0.0 were each built once against Vite 8.3.5 in a temp project. They were not tried under `vite-plus` (`vp`).
- Baseline: the current content script bundled with esbuild from source is **64.5 KB raw / 21.5 KB gz** (ui.ts 21.0 KB, css.ts 12.2 KB, app.ts 12.0 KB, extract.ts 9.3 KB, highlight.ts 4.0 KB). The existing `apps/extension/dist/content.js` is 93.0 KB raw / 26.5 KB gz, but that dist looks like a test build (unminified, `SPEAKKIT_TEST`), so it is not used as the baseline.
- `@speakkit/ui` (the Lumen kit) is imported by no file in `apps/extension/src` or `apps/desktop/src` (grep found none). The extension has its own `src/ui/components.tsx`, the desktop renderer has its own `ui.tsx` (Btn, Toggle, Badge). The kit is therefore duplicated, not shared.

## Prioritized swap plan

1. **valibot in `packages/protocol`** (server `validateSpeak`, `normalizeSettings`). Smallest, safest, biggest hardening win (wire data is currently unchecked at runtime). After: `pnpm --filter @speakkit/server test`, `pnpm --filter @speakkit/extension test` (settings tests with literal bad values), extension build still has 0 bytes of valibot in `content.js` (grep the bundle).
2. **Radix primitives under Lumen CSS, and make `@speakkit/ui` the single kit** (replace `overlay.tsx`, slider/toggle/tabs behaviour; delete the extension and desktop local copies). Do one component family per commit (Switch, Slider, Tabs first; Select, Menu, Popover, Dialog, Tooltip next). After each: `packages/ui` unit and browser tests, `compare` visual diff against `lumen-spec.json`, keyboard e2e in popup/options, desktop smoke test. Watch the visual snapshots (e2e/visual) for focus rings and portal z-index.
3. **`@webext-core/messaging` spike, then migration.** Spike first on one message (`get-health`) end to end, including service-worker restart. Then migrate bg, popup, options, side panel, offscreen. Decide content script (package or 10-line wrapper) from the measured +1.4 KB gz. After: `background.test.ts`, `player.integration.test.ts`, e2e `playback.spec.ts`, `content.spec.ts`, `perf.spec.ts` (check content-script startup did not regress).
4. **`@soundtouchjs/audio-worklet` in the offscreen player** for pitch-preserving speeds above 2x. After: `player.test.ts` (fake context needs a stub for the worklet node), e2e playback at 2.5x and 3x with the `__speakkit.rms()` hook, listening check for gapless joins between sentences.
5. **Electron small wins**: `electron-log`, `electron-store`. After: `apps/desktop/tests/smoke.test.ts`, first-run wizard flow.
6. **`electron-builder`** when the first installer is needed; `electron-updater` after signing and hosting exist.
7. **Later, driven by features**: Readability + unpdf + tesseract.js + EPUB/DOCX parsers for the reader and library; a TTS text normalizer after a listening test; tinykeys if in-page shortcuts become configurable; WXT or electron-vite only if the build becomes a maintenance cost.

## Not verified
- Sizes use esbuild, not Rolldown; the content-script baseline came from a source rebuild, not from the shipped `dist`.
- WXT and crxjs were built under plain Vite 8.3.5 only, never under `vite-plus`. `vite-plugin-web-extension` and `electron-vite` were not built at all.
- `@webext-core/messaging` behaviour with service-worker restarts, offscreen targets and tab push was read from its metadata, not run.
- `@soundtouchjs/audio-worklet` was only bundled, not played; latency, CSP and gapless behaviour in Chrome are untested.
- Radix, Base UI, Aria and Ark were bundled, not rendered; accessibility parity with the Lumen spec is untested.
- `Intl.Segmenter` abbreviation behaviour was checked in Node 24 only.
- No comparison of `findMainRoot` against Readability on real pages was run; the rejection rests on the live-`Range` requirement and the size.
- English TTS normalizer packages: one search only. EPUB, PDF, OCR, DOCX packages: metadata and README claims only.
- Whether kokoro-js already phonemizes numbers and abbreviations acceptably was not tested.
